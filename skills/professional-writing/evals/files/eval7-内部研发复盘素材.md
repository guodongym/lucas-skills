# 研发两周复盘素材（主仓 mercury）

- 统计周期：2026-11-12 至 2026-11-26，主应用仓库 `mercury` 共 46 个 PR（39 已合并、4 在途、3 废弃）。
- 交付节点：距首个内测交付节点 2026-12-10 仅剩 5 个工作日，当前排期评估剩余工作量约 42–60 人日，不可能全塞进 12-10。
- 会议定位：团队内部熟人复盘，对事不对人，把返工和堵点理清，今晚现场拍板关键口径与节奏。

## 现象与事实记录

1. **大 PR 返工与事前不对齐**
   - 团队用 Agent 编码后产出很快，但事前没当面拉齐边界，靠 AI 闷头做大再提审。
   - PR `#44`（画布快照恢复）：单 PR 攒到 41 个文件（`+4,120 / -680`），混入历史面板、生图、生视频 3 个独立改动，中途 4 次合主线；前端还单边塞了未约定字段 `snapshot_meta`（后端 V2 接口静默丢弃），最终整单废弃，拆成 3 个小 PR 重来（首个拆分 PR `#56` 仅 11 个文件、`+890 / -170`）。
   - PR `#47`、`#48` 来回拉锯严重，分别推送 12 次/10 条评审、9 次/11 条评审。
   - 11-24 已合入小 PR 约定（单 PR 控制 0.5–1 人日、按天提审），但落地还不稳定。

2. **过程缺同步、设计 PR 积压、台账脱节**
   - 2 份总设计 PR（`#42` 审计设计、`#53` 插件对接设计）挂了 2 天仍是 0 评审回复，卡着下游开工。
   - 规范要求以 `TAPD` 为进度真相，但多条在途 PR 仍未填任务号。
   - 原迭代必交项“飞书回调接入（3 人日）”在 11-12 至 11-26 期间在 `mercury` 仓库查不到任何提交或 PR 记录（需今晚当面核实实际进度及是否卡在外部权限）。

3. **产品原则与权限口径滞后引发返工**
   - 11-23 才正式定下两条权限总原则：① 一期只保留平台+项目两层；② 项目内协作默认向正式成员开放，临时成员可见自己提交的成果。
   - 定口径前已写完的 PR `#34`（细粒度组长管理）直接废弃；而 11-24 新提的 PR `#51`（资产历史）依然和刚定下的原则打架：普通正式成员点“团队”仍只能看自己，临时成员被整体拦截。

4. **代码评审压在单点 + 缺基础 CI**
   - 统计周期内 PR `#11`–`#56` 中成员提交的 16 个 PR（已排除作者自评和自批）：
     - 非作者评审共 32 次：技术负责人承担 28 次（87.5%），同伴互审 4 次（12.5%）。
     - 非作者最终批准共 9 次：技术负责人承担 8 次（88.9%），同伴互批 1 次（11.1%）。
     - 有同伴（非作者且非技术负责人）参与评审的成员 PR 仅 2 / 16 个（12.5%）。
   - 目前未配置基础 CI 门禁，评审全靠本机拉代码复跑，各人环境缺依赖导致结果不一致。

5. **`218` 测试环境部署严重滞后**
   - `v0.4.0` 在 11-23 发布后尚未部署到 `218`；之后主线又合入 6 个重要 PR，其中 4 个涉及数据库结构变更或迁移（`#49` 账号软删停机迁移、`#50` 字段重命名、`#52` 审计表迁移、`#55` 索引重建），2 个为纯功能增量。多笔迁移攒一起上线排障与回退风险升高。

6. **上游依赖未前置探针**
   - `UniModel` 网关直到 11-24 实测才发现清单里 2 个型号报 403/503、另有 12 个型号未开通或报错；反观 PR `#54` 先拿预发凭证跑通探针再写代码，当天顺利合入。

## 今晚建议推进的改进与待拍板事项

- 改进方向：写代码前 15 分钟当面对齐方案与拆分表；落实单 PR 0.5–1 人日按天提审；每日 15 分钟短日会（昨日合入 / 今日小 PR / 卡点与待审）+ 补齐 TAPD 号；跨模块口径当天同步在途分支；A/B 级 PR 放开给模块同伴交叉终审、C 级与总设计联合把关并补基础 CI；`218` 定固定同步窗口并先做迁移演练；上游外部依赖先跑通 1 条最小真实探针再定案。
- 今晚必须现场拍板的 3 件事：
  1. 敲定 PR `#51` 权限修正与分期拆分范围；
  2. 锁定 12-10 必保内测场景子集，确定 `218` 迁移演练与部署窗口；
  3. 确定每日短日会时间、各模块同伴互审配对关系、基础 CI 牵头人，并核实飞书回调接入的实际进度。
