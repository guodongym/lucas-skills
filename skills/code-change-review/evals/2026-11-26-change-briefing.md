# 2026-11-26 改动导读、PR 适配、新概念质疑与零信任立场校准

基线为 `b48035d`（v0.12.0）。设计见上游仓库 `docs/superpowers/specs/2026-11-26-code-change-review-change-briefing-design.md`。本次在原审查前加入零信任立场与详细纯事实的改动导读，并在“是否需要一起交付”加入新概念质疑与 PR 适配判断；报告改为一行结论 → 导读 → 特别提醒与完整判定 → 五问 → 具体问题，并按“一处展开、别处引用编号”消除跨节复述。原有 58 条用例和断言保持原样，分两批追加 9 条行为用例。

## 拆分规则的取舍

PR 适配提炼自结构化 PR 拆分原则的核心思路：PR 边界看能否独立说明、验证、决定合并或撤回，以及评审者能否看清关键差异，不看作者耗时或体量。落到 Skill 时改写为评审阶段的三个问题（能否单独交付、值不值得拆、拆开是否有害）。具体仓库的风险面清单、固定行数阈值、分支时长提醒和专有术语均不写入；目标仓库有这类规则时在审查时读取，强制规则被违反按 C 处理，其余拆分建议不阻塞合并。

## 第三批：零信任立场与报告去重（2026-11-27）

针对第二轮发现的两个问题——大 PR 报告达 29,503 字符（导读新概念表、特别关注、五问与九面反复复述同一批内容），以及开头隐含“默认大方向合理”的合规姿态导致出现无证据的礼貌性肯定——做两处收敛：

1. **前置 `## Stance`**：确立“零信任调查、证据门槛定级”——需求、PR 描述、自带文档、方案抽象、测试绿灯和既往主张一律视为未证实假设，默认新增概念不必要直至用户任务证明必要，禁止无证据的客套肯定；阻塞门槛保持严格，未证实的合理性/过度设计质疑直接写透并标为非阻塞评审判断。
2. **保导读、删复述**：改动导读保持详细、完整且纯事实（新概念清单只列类别、概念与来源，不再提前写处置方案）；全报告遵守“一条事实或问题只展开一次、别处引用编号”，将特别关注压为单行清单、五问压为每问 2–3 句纯判断（新概念质疑与保留/简化/拆分/移除集中写在“方案”）、九面中已改动面只标“无异常”或对应 `C/P/Q` 编号。
