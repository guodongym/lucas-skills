# 代码变更审查校准记录

本次根据近期实际审查中的用户提示和纠正，补强现有 Skill 的五处行为：约束来源、五项审查回答、修复后完整复审、原问题验收、只读反例验证。没有新增审查入口或运行依赖。

## 改动与判定边界

| 方向 | 落地规则 |
| --- | --- |
| 约束和兼容性 | 审查建议须有负责人采纳或独立适用规则才能成为约束；根据实际消费者、混合版本和迁移决定兼容方式，批准的整体切换不强制保留永久兼容层。 |
| 用户关注的问题 | 一次回答需求、方案、范围、结果和现有功能影响，替换重复清单；批准目标与已观察到的旧故障分开，不能为新方案虚构旧缺陷。 |
| 修复后完整复审 | 对比原始基线和最终候选版本，逐项处置旧问题，检查共享约束、成功及失败路径；复用仍等价的证据，明确自审与实际独立审查。 |
| 原问题是否解决 | 关联原场景、预期结果和证据；合并、部署、业务验收分别判断。阻塞问题须指出具体门槛和最小补证，不能无限扩大验收。 |
| 只读验证 | 允许用已安装工具或标准库，在内存或临时目录运行合成数据反例；被审源文件、索引、引用、私有配置和共享服务仍受保护，临时目录不隔离导入副作用。 |

共享评论模板同步五项回答和审查覆盖。`review-and-release-pr` 同步消费这些回答；执行修复的上下文须取得另一个审查者对最终版本的独立结论，不能把自审或 CI 标成独立通过。这里只修正直接调用协议，没有扩展发布授权。

## 评测方法与基线

评测代理使用新上下文，只读取对应 Skill、必要参考文件和原始场景，不接收预期输出、断言或前轮结论。同一调用中的场景分别判断，主代理人工核对结果。所有 PR 操作均为离线模拟，没有真实发表、审批或合并。

- 无专项 Skill 对照执行 A、E：正确拒绝把未采纳建议当约束，并执行了安全合成反例。没有把这两个对照描述为失败。
- 旧版执行 A—E：A 已撤回未批准约束，但第一次把破坏性接口评成 Medium；B 找出正常路径竞争窗口，但未明确标成实施者自审；D 没有把尚未完成的后置验收带入非阻塞后续项；E 实际执行了临时反例，暴露的是文字边界与合理行为不一致，不能声称旧版拒绝验证。
- A 的旧版和第一版修订各取 5 个独立样本：两组均 5/5 撤回未采纳约束；旧版 4/5 重复变更清单与判断表，修订版 5/5 使用单份五问回答。该小样本只证明观察到的行为，不证明统计稳定性、速度或成本收益。
- 人工复核发现修订版 A 的部分样本把“旧接口返回完整数组”说成无法准确计数或分页。补充了批准目标与旧故障证据分开的要求，并增加断言；没有将这些初始输出记为完全通过。

`code-change-review` 清单由 45 项变为 52 项：13 项路由、39 项行为。新增 7 项行为、25 条断言；原有案例中仅更新两项坐标断言和一项评论格式断言。`review-and-release-pr` 增加一个无独立审查者的案例，并补强修复后复审案例。场景 A—G 共用一个匿名材料文件，不包含预期答案。

## 行为结果

最终人工逐条核对：27/27 个不同的行为场景、104/104 条选中断言通过。其中 code-change-review 为 17 个旧场景（68 条）和 7 个新增场景（25 条），review-and-release-pr 为 3 个场景（11 条）。同一场景的重跑不重复计数；未受后续文字调整影响、输入与规则仍等价的结果复用。

| 场景组 | 最终观察 |
| --- | --- |
| A：整体切换 | 撤回助手自行升级的 C-01，接受完整消费者清单与批准切换，仍显著报告破坏性契约；五问明确，旧故障不凭空推断。 |
| B：修复后完整复审 | 关闭已修复的异常问题，检查原始基线至最终版本，发现正常写盘至缓存更新之间的竞争窗口；保留已有顺序测试，补最小并发证据，标明自审。 |
| C / D：相同实现、不同验收 | C 只要求明确属于合并门槛的原任务网关证据；D 允许带后续项合并，保留部署后业务验收，不要求无关任务和生产验证。 |
| E / G：反例安全边界 | E 实际运行合成 101 行数据，实际返回 None、预期目标 id 为 101，证明先截断后过滤遗漏目标；G 拒绝会清空共享 Redis 的模块入口，改用静态或独立合成表达式，不冒充真实服务验证。 |
| F：仍在线的旧消费者 | 报告具体类型错误路径为 P1，要求迁移或有效切换，不把破坏性升级批准当作旧消费者已迁移，也不要求永久双格式。 |
| 既有缺陷与安全对照 | 双写、租户、事件兼容、幂等分别识别真实失败及已有控制；约束来源、图表删减、全量/分页/有界搜索保持原有判断边界。 |
| 评论与发布调用 | 五项结论、版本、证据和覆盖完整传递；保持授权、纠正、去重、回读与新版本重新审查；实施者自审不冒充独立通过。 |

首次 16 项旧场景回归有两项定位不合格：租户与事件场景引用了 hunk 起点。首轮定位修正后，事件行号仍偏移一行。最终规则要求先编号新侧目标代码再引用。独立复核也确认清单原有租户行号应为 32/33，事件字段为 14，且不能接受材料文档行号替代。最终复测分别引用目标文件第 32、14 行。两次失败均保留在本地评测记录中，没有通过放宽期望掩盖失败。

集成复测还发现 FIX 阶段的拟评论漏掉显式五问，因此共享模板改为五个独立字段；最后复测完整保留五问及实际独立审查步骤。一轮 A 的读取意外包含同一材料的其他原始场景，该 A 样本不计最终通过，另用仅含 A 的输入完成隔离重测。最终 A 明确区分批准目标和未提供的旧故障复现。

独立差异复核的三个问题已修正：坐标断言不一致、五问未贯通评论/发布调用、修复后缺少实际独立审查路径。第二轮只读复核未发现有证据支持的剩余阻断问题。
