# 代码审查补充用户可见界面检查

2026-11-03，基线 `7aff9d2`。本次只调整 `code-change-review`：增加用户可见界面这一检查面、运行时走查和必填的界面覆盖说明，不新增 Skill、项目依赖或评测执行器。

## 问题来源

x-scraper PR #225（159 个文件，+7995/−194）第一轮深度审查只覆盖后端和上一轮评论里的后端问题。报告没有提到界面规则、组件复用或页面走查。维护者追问“界面也看一下”之后，第二轮用合成数据启动页面，才查出 13 项界面问题：Markdown 原样显示、加载时误显示空状态、原始枚举和 ISO 时间、按钮分散与主次不清、自由文本代替日期和时间控件、弹窗和表单不合规、列表缺关键列、未复用同类模块的共用组件等。

对照旧版 Skill：八个筛查面里没有用户可见界面；风险表把所有界面改动归为“low-risk UI”；只读验证没有说明能否启动预览。

## 改动与边界

- 筛查面从八个增加到九个，新增“用户可见界面”。评审维度新增对应检查：沿主任务路径检查状态、原始值、操作主次与对齐、表单和弹窗、目标宽度下的布局，并对照最接近的同类功能检查组件复用。
- 仓库写明“必须”的界面或组件规则按已批准约束处理，违反时记为 C，不当作风格偏好。
- 只有存在安全隔离的预览方式时，才在本机启动文档写明的模拟数据模式或静态服务，走查改动页面；否则写明未走查及其影响的门槛。纯文案或样式变量改动只核对改动本身。
- 输出模板和 PR 评论新增必填的“UI coverage / 界面覆盖”行。仓库要求合并前提供走查证据，而评审者和作者都没有提供时，结论不能是可合并。
- 大改动中，每个检查面单独记录覆盖情况；某一层的问题或上一轮评论不能代替其他层，没审到的检查面写成未验证，不得省略。

## 方法

沿用 2026-10-30 的做法：从真实问题提炼脱敏场景，输入与断言分开保存；每次回放使用不继承主会话的独立上下文，只提供对应版本的 Skill 和一个场景，不提供断言或疑似问题；全部使用当前模型。

| 场景 | 内容 |
| --- | --- |
| A | 离线材料，仿照 PR #225：新增 4 个页面，带界面缺陷、需求偏离和后端续采缺陷，界面规则直接列在材料里 |
| B | A 的安全对照：组件复用正确，作者附走查记录 |
| C | 已有页面只改按钮文案 |
| D | 小型 Git 仓库，界面规则分散在 AGENTS.md、DESIGN.md 和规范文档中 |
| E | 在 D 的基础上后端已按上一轮意见修好，提问只问“意见是否修好、有没有 bug” |
| F | 可以启动的静态后台页面，README 写明模拟数据预览命令，缺陷只有运行后才完全可见 |
| G | PR #225 原样回放：代码冻结在第一轮审查时的 `7d5894c4...0af4c990`，提供当时的 PR 描述、维护者评论和 #101 v0.8 方案，不提供后来的界面评论 |

A、B、C 写入 `evals.json`（58 项，其中行为用例 45 项）；D–G 依赖临时 Git 仓库或真实仓库对象，只作为本次记录。

## 结果

旧版（`7aff9d2`）在 A×2、B、C、D×2、E×2、F×2 共 11 次受控回放中都查出了界面问题，也没有在 B、C 中误报。F 的两次回放都主动导出快照、启动预览，用 Playwright 在 1440 和 1280 宽度下走查。说明在小场景里，旧版只要读到前端就能审好。

真实漏检只在大规模场景中复现。G 的旧版回放和当时的生产审查一致：306 行报告完全没有界面规则、组件复用或页面走查。

## 限制

- G 的新版没有逐项列出相对 QQ 缺少的 `ListToolbar`、`RowActions`、`Descriptions`、`StatusTag`，也没有指出按钮对齐、主次和加载状态；它把 1366、1280 宽度和真实后端的加载、错误状态列为未走查。收紧“复用”措辞需要重跑 G，本次没有做未经评测的修改。
- G 只回放了新旧各一次，A、B、C、F 的新版各一次；样本量不能证明漏检率稳定下降，也不能说明耗时变化。
- 清单中其余 55 个案例本次未执行模型回放；静态清单检查不能替代行为结果。
- 运行时走查只覆盖 Chromium；所有页面数据均为合成数据，没有访问真实服务或 GitHub。
