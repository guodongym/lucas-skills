# WPS CLI 授权与凭证排错

用于缺少 scope、`invalid_scope`、登录保存失败、默认读取旧凭证、`data passed to Set was too big` 或 `invalid_grant`。以下存储问题曾在 macOS CLI 0.3.6 验证；其他版本先核对现场，不假定回退行为、大小阈值或权限数量固定。

## 先分清权限与登录

- 应用在开发者后台开通的能力、用户令牌实际授予的 scope、企业套餐权益、目标文件访问权限是不同层次。应用已开通文档读写，不代表本机令牌已获得它；`user me` 成功也不代表文档接口可用。
- `auth status` 检查身份、有效期、`granted_scopes` 和配置目录；只输出必要状态，不使用 `auth token` 打印凭证。先保留现有应用绑定，不把重建应用或 `auth clean --force` 当排错起点。
- 补用户授权使用 `auth login --device --scopes "<本次所需权限>"`，显式列出 scope，保持进程直到领取并保存凭证后自行退出。不要只看到网页授权成功便终止进程或宣布配置完成。设备码流程以快速接入说明为准，不照搬公共规则中省略 `--device` 的旧登录示例。
- 用户要求全部权限时，区分用户授权（delegated）与应用身份（app），以当前官方定义和后台可申请项核对范围。不能把 spec 中所有 scope 混入同一次用户授权，也不能把历史获批数量当永久清单。新增权限按宿主授权规则处理；既有业务写入授权不自动变成扩大应用权限的授权。
- `invalid_scope` 只证明该项请求被拒绝；核对名称、身份类型及后台状态，不能直接归因为套餐不足。记录已申请、已授予和被拒绝的集合；仅明确拒绝某项且其余仍有进展时，才有界重试其余项，不无限逐项试探。最终以 `granted_scopes` 核对结果，未授予项保持未完成，不能将部分成功称为全部开放。

## 登录后验收

1. 确认登录进程退出成功，再从新的命令进程运行默认 `auth status`，核对实际 scope 与有效期。
2. 默认环境运行 `user me --token-type delegated`，确认身份，再执行用户指定的有界只读查询；不为验证权限发送邮件、消息或试写真实文档。
3. 新增授权或修复存储后，用 `auth refresh --delegated` 验证续期，再核对默认状态与一次只读调用。日常读取无需每次强制刷新。续期会更新本机凭证，需要正常安全存储写权限。
4. 报告已验证能力与剩余限制。即使读取通过，也不要宣称所有写能力或企业权益均已验证。

## 保存成功，但默认仍读到旧凭证

典型证据：登录报告 `delegated token saved`，默认状态却仍是旧有效期或旧 scope；显式文件后端显示新授权。先做只读对照：

```bash
wps365-cli auth status
WPS365_KEYRING_BACKEND=file wps365-cli auth status
WPS365_KEYRING_BACKEND=keychain wps365-cli auth status
```

- 同时核对 `WPS365_CONFIG_DIR`、`WPS365_KEYRING_BACKEND` 与实际 CLI 路径，避免不同目录、版本或环境混用；不要输出密钥环境变量。
- macOS 上曾出现新凭证因钥匙串写入大小限制转存加密文件，旧钥匙串记录仍被默认读取。只有对照结果支持时，才按此诊断；`data passed to Set was too big` 不是 OAuth 权限不足，反复增加 scope 或强制重试钥匙串不能解决它。
- 显式文件后端适合诊断，不要直接永久设置为 `file`：应用密钥可能仍在钥匙串，文件后端的 `client_secret_configured` 可能为 false，短期访问成功不能证明可以续期。
- 只有已定位为过期旧登录记录遮蔽有效新记录、且用户已授权修复登录时，才清理该旧记录。先检查当前版本 `auth logout --help`；保留新 `token_delegated.enc` 及其配套 `keyring.key` 的可恢复副本，不解密、不打印，放在内存或受限临时目录，文件权限保留 `0600`。不能删除应用绑定、应用密钥或整套钥匙串。
- 可使用限定后端的 `WPS365_KEYRING_BACKEND=keychain wps365-cli auth logout` 清理旧用户登录记录；不能假定它只影响钥匙串，执行后检查并恢复被影响的新加密文件。恢复完成后，必须在不加后端覆盖的默认环境完成上述验收；仅显式 `file` 查询通过不能算默认 CLI 已修好。验证后清除本次临时凭证副本。

## 保存或续期失败

| 实际症状 | 处理 |
| --- | --- |
| 写配置目录或 `keyring.key` 报 `operation not permitted` | 区分执行沙箱与 WPS 权限；按宿主流程取得必要本机写权限后重试同范围登录，不关闭安全机制，不改存明文凭证。 |
| 网页授权成功，CLI 保存失败 | 授权尚未完成本机配置；保持原可用记录，修复保存问题后重新领取并验证。 |
| `invalid_grant` / `refresh token ... not_found` | 核对实际读取的后端、应用及最新凭证；不能凭此断言 scope 不足。新旧记录冲突解决后仍失败时，保留恢复副本，清理对应本地用户登录记录，再做同范围设备码登录并验证续期。 |
| `auth login` 立即返回原有效期 | 可能复用了有效访问令牌，不能将其视为已取得新续期凭证。只有确需重新领取时才按上一项处理，不反复运行相同登录命令。 |

修复失败时恢复原可用加密记录，并明确当前访问与续期各自是否可用；不要把剩余问题隐藏为“已配好”。
