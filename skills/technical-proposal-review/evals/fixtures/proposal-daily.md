# Review materials

用户请求：请审阅下面这版社群日报方案，看看能否作为开发依据，并说明必要的调整。只审阅，不修改文件或连接外部服务。

已确认目标：运营每天查看前一天的讨论摘要和待跟进提问；从原文提取反馈后，进入已有分析、人工审核流程。不要求实时响应、不要求跨日跟单。

现有能力：定时任务、按范围读取消息、去重保存、失败分页恢复、模型批处理、反馈修订与人工审核均已存在；新平台只需适配读取及来源类型。

方案 v3：首版按配置的时区每天生成一份日报，使用发送日期选择消息并保存报告及依据；独立开启采集和反馈提取。保留权限检查、去重、失败恢复、报告历史和引用。新增五张表分别保存连接配置、频道进度、当前消息、采集轮次和日报版本。

另外规定：日报必须精确还原业务日零点的消息版本，因此为截止后编辑的消息寻找旧原文；运行后修改历史起点将同时改动补采进度与自动提取范围；已处理消息被编辑时自动更新已生成反馈。二期拟使用实时事件连接，但当前没有实时验收指标。

开工前需完成：平台权限与样本读取，核对现有流程接入点，验证多语言样本的提问判断；另须先搭建完整产品并做恢复故障演练、最高容量试验、全量回归。

方案作者意见：五张表职责清楚，复用了旧能力，所以无需继续精简；上述验证全部通过后才能写正式产品代码。
