# Review materials

用户请求：复审业务操作日志方案，看看修订后还有没有实质问题。只读。

最新批准决定：审计异步保存，不阻止人工业务写入。内存有界队列满或进程退出前未保存可能丢失记录，负责人已明确接受该边界；需要报警和缺口说明，不做磁盘待写文件、重放服务或额外中间件。这个取舍来自负责人在本次会话中的明确答复，不是作者自行声称。核心事实为操作者、时间、动作、对象、变更、结果和关联产出，必须用操作时快照。

现有事务服务顺序：重新授权 -> 调用业务回调 -> 提交数据库事务 -> 返回请求结果。数据库 commit 失败会抛异常，业务回调返回不等于提交完成。

修订方案：装饰器在业务回调返回成功时，立即将记录按 result=success 入队；事务服务随后提交。消费者从入队快照保存日志。失败重试不改原事件的 success 字段。前轮关于身份快照的意见已修复，记录来自重新授权后的身份上下文。系统会记录队列丢弃计数并展示可靠性边界。
