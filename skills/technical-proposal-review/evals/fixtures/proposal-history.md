# Review materials

用户请求：我们想让运营用起来简单一些，请审阅这个舆情分析改造方案，说明调整建议。只读，不写代码。

已确认业务：按关键词持续采集并入库。舆情分析只消费入库内容，不能启停或改变共享采集。运营需要设置专题、持续查看好差评、核查原文和人工纠错，还要查看过去分析结果及当时依据，比较判断为何变化，并导出材料。

现状：四个页签为结论、讨论证据、分析设置、运行记录；各页有直接入口。已能一次配置后自动处理新入库内容。运行记录可取消与重试；纠错会保存新报告。主要已知问题是新入库内容超过前 5000 条后无法进入分析，以及观点只输出笼统分类。

拟改方案：删除历史结果，只保留明确导出的报告；将四页缩成结论和证据；新增一个“监测”主开关，同时负责共享关键词采集、旧帖跟踪及专题分析。为处理共用关键词的专题，再增加一层任务归属与协调关系。保留原文与纠错。作者认为入口更少，所以结构更简单。
