# Codex 用户可读语言策略设计

- 日期：2026-08-11
- 状态：设计已确认，待实施
- 结论：Codex 面向用户的解释默认使用中文；机器依赖的技术原文保持不变，并在可能影响理解时于首次出现处补充中文含义。

## 1. 要解决的问题

现有全局规则只要求“默认使用中文”和“有标准术语的概念用标准术语”，没有区分普通叙述与机器依赖的技术原文。Agent 因此可能直接用英文标识或术语组织中文回答，用户需要猜测这些词的含义。

近期 6 个 Codex 任务的抽样中，5 个在面向用户的正文或标题里混用了可以直接中文化的英文表达。代表性截图的一段说明至少包含 17 个不同英文词，包括协议动作、状态值、组件名和普通技术术语。问题不是英文是否允许出现，而是英文原文没有与中文解释建立清晰映射。

## 2. 目标与非目标

### 2.1 目标

1. 用户不需要猜测英文含义，即可理解结论、依据和下一步。
2. 代码标识符、枚举值、字段名、接口、命令、路径、日志、报错和产品名称保持原样。
3. 标题、表格和图示与解释性正文遵循同一规则。
4. 规则保持简短，不维护固定术语表。

### 2.2 非目标

- 不禁止英文，也不翻译机器依赖的原始内容。
- 不改变英文仓库中代码、文档和其他交付物的语言。
- 不要求对已经清楚、且不影响理解的每个缩写重复解释。

## 3. 定稿规则

在 `AGENTS.md` 的“语言策略”中使用以下规则：

```markdown
- **语言策略**:
  - **交互**: 默认使用中文。面向用户的解释有自然中文表达时，不用英文充当普通叙述。
  - **技术原文**: 代码标识符、枚举值、字段名、接口、命令、路径、日志、报错和产品名称保持原样。它们首次出现在解释性正文、表格或图示中且会影响理解时，写成“中文含义（`原文`）”；后文优先使用中文，仅在需要对照实现时附原文。
  - **交付物**: 自动适配项目现有语言环境；英文仓库用英文。
  - **自检**: 除代码、命令、原文引用和按仓库语言生成的交付物外，用户无需猜测英文即可理解结论、依据和下一步。
```

同时将风格规则中的“有标准术语的概念用标准术语”改为：

> 除需精确保留的技术原文外，其余用白话；不用比喻、隐喻或内部黑话。

## 4. 验收

使用代表性协议说明进行新任务复测，必须同时满足：

1. `unknown`、`blocked` 等真实状态值仍然保留。
2. 影响理解的技术原文首次出现时带有中文含义。
3. 去掉括号内的技术原文后，中文句子仍能完整表达结论。
4. 命令、路径、日志、报错及英文仓库交付物没有被错误翻译。
