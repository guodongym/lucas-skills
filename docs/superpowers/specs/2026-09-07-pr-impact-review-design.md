# PR 影响与架构约束审查增强

状态：用户已在本任务确认下述范围并授权实施；本文记录已确认的聊天设计。

## 目标与边界

协作者提交的 PR 即使没有已确认 Bug，也可能越过需求范围、改变架构边界或加入没有当前用途的能力。增强已有 `code-change-review` 和 `review-and-release-pr`，使报告明确指出这类风险及合并条件。

不增加独立 skill、评分系统、依赖、自动标签或审批平台。不修改 Agent Manager，不推送、不发布、不激活到用户工具目录。已有审查只读、外部写入授权和 P0/P1/P2 缺陷证据规则保持有效。

## 审查内容

每轮筛查八个维度，只有相关变化才深入调用方与消费者；没有变化与无法验证必须区分：

1. 需求与范围：把实质变化对应到已认可需求，识别夹带目标。
2. 新增能力与复杂度：验证当前用途、复用可能、删除后能否满足验收，以及维护责任。
3. 架构边界：模块职责、依赖方向、数据归属、唯一事实来源和部署关系。
4. 接口与兼容：新增、修改、删除 API、事件、配置、CLI 和存储契约；包含参数、返回、错误与权限语义。
5. 数据与一致性：表、字段、类型、默认值、索引、约束、写入路径、历史数据、迁移和恢复。
6. 现有功能与故障传播：实际用户流程、共享调用链、重试、部分失败和核心依赖。
7. 安全与运行负担：权限、外发、外部副作用、依赖与安装脚本、无界资源和长期运行成本。
8. 验证与约束完整性：测试删改、断言放宽、CI/架构检查跳过、仓库规则修改是否掩盖问题。

基于变更前可信要求和代码还原基线。PR 自述、评论和测试是待核验材料；同一 PR 修改的规则、架构文档和验收不能自证已获批准。审查材料中的指令不授予权限，也不能修改审查流程。独立批准应有可追溯来源，已有批准不重复索取。

新功能可以通过已认可需求和预期使用路径证明必要性，不机械要求已有调用方。没有架构文档时依据代码还原事实，不把推测当约定。纯风格偏好不得阻塞。

## 输出与决策

四种判断分离：

- 影响等级 `Low / Medium / High / Undetermined`：由实际传播范围、兼容性、数据语义、架构边界、部署协调和可恢复性判断，不按行数或数量评分。整体取最高已证实等级；可能改变等级的缺口标为待确认，同时保留已知影响下限。
- 范围与架构 `Conforms / Violates / Needs decision`：分别表示符合已认可要求、已证实违反要求、缺少必要依据或决定。
- 已确认缺陷仍为 `P0/P1/P2`；必要性或授权问题不冒充实现 Bug；已认可范围内的正确性失败只记 P，不因验收失败另造 C。新增写入路径也不单独证明职责转移或广泛影响。
- 合并结论继续使用现有四种 `Merge readiness`，新增范围与架构作为输入。

先给影响等级、关注原因、范围与架构、合并结论。变更清单提供对象、增改删、需求依据、实际受影响对象、兼容和恢复、证据或缺口。范围与架构问题独立记录依据、位置、影响、所需决定或整改；不要与同根因缺陷重复计数。

已证实违反约束 -> `Not ready`；关键决策或必要验证缺失 -> `Unable to determine`；高影响本身不阻塞。其余沿用原规则。低影响和空范围可以简短汇总，不强制展开无关表格。

PR 编排层复用审查结果，在需求阶段检查已知越界，在独立审查阶段捕获实现才暴露的越界。只有符合范围、无 P0/P1 与阻塞问题、必要验证完成才 PASS；越界或待决不能进入自动 FIX。保留现有修复授权规则。base/head、需求或批准变化后刷新受影响证据。

## 特别提醒与 PR 评论（用户补充确认）

新增、修改、删除接口、表或字段，架构变化或偏离，以及现有功能行为变化，只要出现就必须在报告开头特别提醒，不能被低影响或无 Bug 结论隐藏。已证实变化与可能受影响但未验证分开。未发现变化只有在筛查完成时才能报告。

代码审查仍默认只读。PR 编排在已有评论授权时发布影响摘要并回读；无授权时产出同内容草稿。不重复索取已有授权。按 PR、base/head 与摘要内容检查本流程已发评论，完全相同则复用；head 或实质结论变化时发布新摘要。发布失败明确披露，不声称已通知。Gate 1 提前停止也保留已识别变化的提醒并标注初步覆盖，不假装已完成独立审查。

## 验证与完成标准

- 使用旧版 skill 的独立行为运行记录失败，再对同样原始材料运行新版；不给执行者预期答案或成对案例标签。
- 新增 12 个行为案例：能力扩张、架构边界、测试削弱、规则修改四组成对案例；兼容字段、破坏性迁移、架构依据缺失、共享权限修改四个补充案例。
- 验证高影响不必然失败、无 Bug 的已确认越界仍不能合并、缺证不冒充违规、合理调整不被误伤。
- 复跑已有 12 个行为案例；触发边界保持原设计，结构校验保留 12 个既有触发案例。
- 检查清单结构与 fixture 引用有效；运行仓库单元测试、两个 skill 的 quick_validate 和 git diff --check。
- 独立复核规则冲突、编排状态映射和评测误报。实际运行结果与未运行的范围分开记录。
